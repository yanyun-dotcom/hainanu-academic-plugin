# 海南大学教务适配

## 适用范围

- 学校：海南大学
- 教务入口：`https://jxgl.hainanu.edu.cn/jsxsd`
- 教务系统：强智科技新一代综合教学管理平台（新强智），学校代码 `10589`
- 登录方式：App 内原生登录，统一身份认证账号密码与图片验证码
- 插件类型：`extension`，扩展内置 `builtin.qz`：登录由本插件实现，学期、课表、成绩、考试与选课复用内置新强智协议

入口依据来自海南大学教务处公开页面，该页把“教务系统”指向 `https://jxgl.hainanu.edu.cn/` 与 `https://jxgl.hainanu.edu.cn/jsxsd/`。

## 登录实现

2026-10-12 实测公开登录页：

- 登录表单提交到 `POST /jsxsd/xk/LoginToXkLdap`，字段为 `userAccount`、`userPassword`、`RANDOMCODE`、`loginMethod` 和隐藏的 `encoded`。
- 图片验证码来自 `/jsxsd/verifycode.servlet`，实际响应为 `image/jpeg`，刷新时追加 `?_=时间戳`。
- 页面登录脚本先取验证码，再用 `conwork.js` 的 `encodeInp()` 计算账号与密码，清空 `userPassword` 后把 `encoded` 与验证码一起提交。

本插件按上述流程原生完成登录：

1. `auth.start` 读取登录页，取出表单字段与提交地址，并按 `encodeInp()` 的算法（按 UTF-16 代码单元做 base64、以 `=` 补齐）计算 `encoded`，随后返回验证码图片。
2. `auth.resume` 把用户输入的验证码填入表单并提交；验证码错误时保留待提交状态并重新给出新图片，密码被拒时返回 `INVALID_CREDENTIALS`，不再重放请求。
3. `auth.validate` 读取学生主框架页面核实会话并返回学号与姓名。

登录页字段与提交地址都从页面本身读取，不写死字段名，也不要求页面必须使用 `<form>` 标签；只跟随一次同源页面跳转。如果改版后仍然认不出登录页，`auth.start` 会返回一条带有限事实的提示（HTTP 状态、正文长度、表单数、密码框数、页面标题，不含账号、URL 与 Cookie），便于反馈而不是猜测页面结构；提交阶段遇到无法识别的响应则转入学校官方登录页。

登录编码串只保留在宿主会话状态中，用于“取验证码”和“提交”这两步之间，登录成功或凭据被拒后立即清除；不写入持久存储、日志、样本或源码。App 不保存密码原文以外的任何学校凭据。

## 使用说明

1. 在教务助手的插件中心安装并启用本插件。
2. 学校搜索中选择“海南大学”，确认教务入口为 `jxgl.hainanu.edu.cn/jsxsd`。
3. 输入统一身份认证账号与密码，按提示填写图片验证码。
4. 登录成功后可使用学期、课表、成绩、成绩明细、考试和选课入口；具体入口与写操作以学校当前开放范围为准。

## 验证范围

已核对教务处公开入口、公开登录页字段、验证码响应类型、登录脚本的 `encodeInp()` 算法与系统厂商特征（强智科技新一代综合教学管理平台）。

离线回归包含 18 个合成用例：登录页与验证码、刷新验证码、验证码错误重试、`encoded` 提交后的身份校验、会话校验、登录页无法识别时的诊断返回、没有 `<form>` 标签的登录页，以及学期、课表、成绩、成绩明细、考试、选课轮次、课程、教学班、已选、选课和退课。全部使用虚构账号并只连接测试桩，不连接真实学校。

尚未完成真实账号、Android 真机、历史学期和选课开放状态验收，因此不得将合成样本结果表述为海南大学真实业务验收；写操作只在合成样本中验证。首次使用真实账号时，请先确认登录成功、课表与成绩能正常显示，再用只读方式核对学期与考试。

## 已知问题与限制

以下问题如实列出，避免误解；欢迎通过本仓库 Issue 反馈或提交 PR。

1. **目前只有 App 内的账号密码登录可用。** App 自带的「教务网页登录 / Cookie 导入」方式在海南大学会以「学校未能返回有效 JSON」结束，不要使用该方式。
   - 已定位到的原因：该方式在解析教务会话时会用到预装的新强智协议，而它要求登录页**内联** `scode`/`sxh` 变量。海南大学的登录页不内联这两个变量，而是由页面脚本请求 `/jsxsd/Logon.do?method=logon&flag=sess`，再用 `conwork.js` 的 `encodeInp()` 拼出 `encoded`（`/jsxsd/xk/LoginToXk` 变体页返回空响应）。预装协议因此把登录页 HTML 当 JSON 解析而报错。本插件的账号密码登录不依赖内联变量，走的是页面自己的 `encodeInp()` 流程。
2. **登录依赖登录页形态。** 字段名与提交地址都从页面读取，并允许跟随一次同源跳转；若改版后仍认不出登录页，`auth.start` 会返回带有限事实的诊断提示（HTTP 状态、正文长度、表单数、密码框数、页面标题，不含账号、URL、Cookie），提交阶段遇到无法识别的响应则转入学校官方登录页。也就是说学校页面大改后，可能需要更新插件版本。
3. **选课与退选写操作只做过合成样本验证**，没有在真实选课开放期间实测；轮次未开放、学分上限、时间冲突、容量不足等返回码尚未核对。
4. **历史学期与页面细节未系统验收**：历史学期、成绩分项、考试座位号等在真实账号上的字段未逐一核对。学校未提供成绩分项时只返回「总评（学校未提供分项）」，不伪造数据。
5. **本地导入的插件不会被 App 自动选中**：需要在学校的教务适配中手动选择本插件并记忆（这是 App 的既有规则；签名上架后可由 App 自动匹配）。
6. **会话内的登录编码串可被还原**：`encoded` 是账号与密码的 base64 拼接，只在「取验证码」和「提交」两步之间保存在宿主会话状态（与内置协议的做法一致），登录成功或被拒后立即清除，不写入持久存储与日志。请避免在他人设备上登录自己的账号。
